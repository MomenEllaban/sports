# ETA GAP — فجوات الفاتورة الإلكترونية بالظبط (ETA-spike)

> المرجع: `src/lib/eta.ts` + `src/app/[locale]/admin/accounting/page.tsx` (سجل الإرسالات).
> التنفيذ الكامل في **T14**. هنا: التوثيق + إعدادات + `Product.gs1Code` فقط — لا تغيير سلوكي.

## الفجوات المؤكدة

### E1 — `itemCode` ثابت `1000001` لكل الأصناف (`eta.ts:192`)
- **المطلوب:** GS1 GTIN حقيقي لكل SKU (من العميل/المحاسب — أكواد GS1 Egypt).
- **الحالة بعد spike:** عمود `Product.gs1Code` موجود (migration `11_gs1`) + بند في قائمة التجهيز. التعبئة في T14 (شاشة منتجات + استيراد CSV).

### E2 — التوقيع الإلكتروني اختياري (`eta.ts:207` يقرأ `ETA_SIGNING_URL` فقط)
- **المطلوب:** خدمة توقيع CAdES-BES (HSM/USB token + SDK) قبل أي إرسال production.
- **الحالة بعد spike:** مفتاح `eta.signingUrl` في Settings (env fallback يبقى). T14 يجعله **إلزامياً** في وضع production (ممنوع submission بدونه).

### E3 — Credit note بأصناف فارغة (`eta.ts:244` → `items: []`)
- **المطلوب:** نفس أصناف الفاتورة الأصلية بكميات سالبة.
- **الحالة بعد spike:** موثقة؛ التنفيذ مع T10 (الاسترداد يمرر الأصناف) + T14.
- **الحالة بعد T-RMA:** credit note المرتجعات يمرر الأصناف الحقيقية (`returns/service.ts` → `submitEtaCreditNote`)، وعند التعثر تُوسم الحالة `PENDING_ETA` ويُلاحقها `pnpm eta:retry` (قسم المرتجعات). الباقي: مراجعة المحاسب قبل production.

### E4 — لا retry queue لحالات `INVALID`
- **المطلوب:** طابور إعادة محاولة + شاشة متابعة (T14).
- **الحالة بعد spike:** الفشل يُسجل `INVALID` مع الرسالة (موجود)؛ إعادة المحاولة اليدوية/الآلية في T14.

### E5 — بيانات الفرع والنشاط ناقصة
- **المطلوب من العميل/المحاسب:** رقم التسجيل الضريبي (موجود `eta.taxRegNumber`) + **كود الفرع لدى ETA** + **كود النشاط** + Client ID/Secret.
- **الحالة بعد spike:** `eta.branchCode` + `eta.activityCode` في Settings وقائمة التجهيز.

## قائمة المطلوب من العميل (مرتبة)
1. التسجيل في منظومة ETA + Client ID/Secret (preprod أولاً).
2. الرقم الضريبي 9 أرقام + كود الفرع + كود النشاط (من البطاقة الضريبية/المحاسب).
3. أكواد GS1 لكل صنف (أو تفويض استخدام كود عام مؤقت في preprod فقط).
4. جهاز/خدمة التوقيع الإلكتروني (HSM أو USB token + رابط خدمة التوقيع).
5. قرار: preprod تجريبي أم production مباشر + staging منفصل (انظر `docs/OPERATIONS.md`).
