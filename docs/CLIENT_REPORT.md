## 1) ما هو النظام؟

نظام إدارة متكامل (ERP) لمتجر رياضة متعدد الفروع — يجمع بين **متجر إلكتروني** (Storefront) و**نقطة بيع** (POS) و**لوحة تحكم كاملة** (Admin) في كيان واحد على منصة واحدة، مع قاعدة بيانات سحابية مشتركة، وعمل 24/7 بدون توقف.

- **المنصة:** الويب (Next.js) — يعمل على الموبايل والتابلت والكمبيوتر.
- **الجمهور:** العميل يشتري أونلاين، الكاشير يبيع من الكاشير، والإدارة تراقب كل شيء مباشرة.
- **الدعم:** عربي + إنجليزي (تبديل فوري بالموقع).

## 2) المميزات بالتفصيل

### 🛒 المتجر الإلكتروني (Storefront)
- كتالوج منتجات (141 منتج فعلي مُسجّل) بتصنيفات وماركات (6 تصنيفات / 8 ماركات).
- نظام طلب كامل: عنوان، دفع عند الاستلام (COD) أو بوابة دفع (Paymob) أو شبكات تحويل، وتتبع شحنة برقم الطلب + رقم الموبايل.
- صفحات: الرئيسية، الكتالوج، الفروع، التتبع، الحساب، و**صفحة مميزات النظام** الجديدة (للتسويق أمام العميل قبل البيع).

### 🧾 الكاشير (POS)
- بيع فوري، خصومات، ضرائب (فاتورة ضريبية إلكترونية مُرقّمة)، باركود، طباعة، **ورديات** (Shift) تُقفل وتحسب الإيراد والسرولة بالكاشير.
- تسديد بأكثر من طريقة (كاش / فيزا / محفظة) مع عمولة/رسوم شحن محسوبة تلقائياً.

### 🏬 المخزون متعدد الفروع (Inventory)
- **مخزون لكل فرع على حدة** (فرع الإبراهيمية + سموحة) مع حركة تحويل بين الفروع.
- جرد دوري (stocktake) وعدّادات، تنبيهات نواقص (أقل من حد معيّن يظهر على الداشبورد).
- **أمر توريد** من موردين مع متابعة المدفوعات للموردين.

### 🔄 المرتجعات والاستبدال (RMA / Returns) — نظام جديد
- **العميل**: يُقدّم طلب مرتجع أونلاين من صفحة التتبع (اختيار المنتج + السبب + صور) مع رقم مرتجع فريد (RTN) ومتابعة الحالة لحظياً.
- **الإدارة**: قبول/رفض، استلام المنتج، **إعادة التخزين** تلقائياً بالمخزون، احتساب مبلغ الاسترداد (خصمياً: رسوم إعادة توزيع عند تغيير الرأي، لا يخصم عند عيب مننا)، ثم **نشر الاسترداد** — كاش أو استرجاع للبوابة أو إنستاباي/فودافون/تحويل بنكي — بشكل آمن ومؤمَّن بحركة محاسبية.
- **الحماية من التكرار**: كل طلب له `clientRequestId` لمنع إرسال نفس الطلب مرتين (idempotency).
- **تأثير على الإيراد**: المرتجعات تُخَصَّم من إيراد/ربحية المنتجات والفروع في تقارير الإدارة (تقرير `reports/summary`).

### 💰 المحاسبة والفواتير (Accounting)
- دفتر أستاذ بالفروع، مصروفات لكل فرع، تقارير الضرائب (ضريبة المبيعات على الطلبات).
- سلف ودفع رواتب للموظفين (Payroll) مع يوميات.
- **تسوية المحفظة** للإيراد من شركات الشحن (COD) — أدخلنا بوابة/رسوم الشحن.

### 📊 التقارير وتحليل الربحية (Reports)
- **ربحية المنتج** (إيراد − تكلفة) مبوبة، **أداء الفروع**، **أداء الكاشير** (مبيعات + خصومات).
- **البضاعة الراكدة** (dead stock): صنف متوفر ولم يُبَع في فترة محددة ليُعاد تسويقه أو تسعيره.
- **أداء شركات الشحن** (تسليم/إرجاع/كاش).
- تقرير **المرتجعات**: أسباب، منتجات، مبالغ مستردة، طلبات ناقصة التعامل.
- كل الأرقام مطابقة لـ `check:invariants` (كل معاملة لها حركة مخزون والعكس).

### 👥 العملاء والولاء
- ملفات عملاء، سجل طلبات، **تقييمات ومراجعات** (تُظهر بعد الموافقة).

### 🔐 الأمان والصلاحيات (التحكم بالنفوذ)
- أدوار: **Super Admin / Branch Manager / Cashier / Finance / Staff**.
- كل صفحة محمية من جهة السيرفر (`requirePageRole`) + صنف وسيط (`middleware`) يقطع الطريق مبكراً.
- **سجل تدقيق (Audit Log)**: كل إجراء حساس (تعديل صلاحيات، حركات مالية...) مسجّل بمن/متى/أي حقل.
- كلمات المرور مشفرة (bcrypt)، جلسات آمنة (jose cookies)، قيود معدل على الحماية العامة.
- **اختبار Rbac-Matrix** يتأكد أن كل API مسجّل ومحمي تلقائياً.

### 🚚 الشحن والتسليم
- ربط شركات الشحن (Mylerz / Bosta / Fawry / Paymob Webhooks) — تحديثات حالة الشحنة سلكياً (webhook) لتصحيح orderStatus تلقائياً.

### ⚙️ لوحة التحكم
- أيقونات KPI مباشرة (إيراد اليوم، طلبات، أصناف، فروع) + رسم بياني 7 أيام + **استعلامات فورية**: مدفوعات معلقة، إيصالات بمراجعة، ورديات مفتوحة، **مرتجعات ناقصة إجراء** (جديد).

## 3) ليش تشتري/تسلم النظام؟

| لماذا؟ | القيمة |
| --- | --- |
| **نظام واحد لا أوراق** | الكاشير + الأونلاين + الإدارة على شاشة واحدة، تداخل لوحات Excel يختفي. |
| **مخزون حي متعدد الفروع** | تعرف كمية كل صنف في كل فرع لحظة بلحظة، تحويلات جرد بدون خلل. |
| **مرتجعات منظمة ومحاسبياً سليمة** | مرتجع العميل شغال، والاسترداد محسوب للنص بالضبط ومطروح من الإيراد — لا "سراويل" بالمخزون أو بالفلوس. |
| **تقارير ربحية صادقة** | ربحية المنتج بعد خصم المرتجعات والخصومات والتكلفة — قرار التسعير على علم. |
| **أمان مؤسسي** | صلاحيات + سجل تدقيق + حماية من التكرار + اختبارات تلقائية قبل كل إصدار. |
| **جاهز للتطوير** | الـ 12 وحدة مبنية من الأول على صندوق البيانات نفسه: إضافة وحدة مستقبلاً (مثل الإنتاج/المبيعات الجملة) بدون إعادة كتابة. |
| **سحب بيانات** | `docs` كامل: RETURNS_AUDIT، ETA، لمحة أمنية، واختبار `dashboard-audit` يفحص الصفحات/اللودرات/الأزرار/الحراسة. |

- `tsc --noEmit` ✅ · `eslint` ✅ (صفر أخطاء) · `prisma` schema متوافق.
- **الاختبارات:** unit 56/56 ✅ ، rbac-matrix ✅ ، dashboard-audit **57/57** ✅ (كل صفحة إدارية لها loader + failsafe + حراسة + كل رابط/زر يوصّل لمسار حقيقي).

### قائمة تحقق مبسطة للتسليم يليه (قبل اليوم الأول الفعلي)
1. مراجعة الإعدادات: الضرائب، حدود الانتهاء، خصومات الشحن، طرق الاسترداد.
2. بيانات مبدئية: مصاريف الفروع، موظفين + صلاحيات، موردين.
3. شريحة تجريبية LIVE للمنتجات/المرتجعات معا (مسار كامل: بيع → مرتجع → استرداد).
4. إدخال بيانات CTA / Paymob / Instapay الحقيقية لكل بوابة (البيئة الآن تجريبية/sandbox).
